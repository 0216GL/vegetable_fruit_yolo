# 双层柿子识别系统 —— 测试结果与分析报告

测试日期：2026-09-26
测试图片：桌面 `qq_pic_merged_*.jpg` 三张
推理参数：`conf = 0.40`、`iou = 0.55`

---

## 一、系统是两层，各管一件事

| | 第 1 层 | 第 2 层 |
|---|---|---|
| **管什么** | 柿子在**哪儿** | 这个柿子**几成熟** |
| **模型** | `models/persimmon_det_v1/best.pt` | `models/persimmon_cls_v1/best.pt` |
| **输入** | 整张图 | 第 1 层裁出来的那一小块 |
| **输出** | 框位置 + 检测置信度 | 4 个成熟度之一 + 置信度 |
| **训练指标** | **mAP50 = 88.23%** | **top1 = 88.89%** |
| **类别数** | 1 类（只叫 `persimmon`） | 4 类（未熟 / 转色期 / 着色期 / 完熟） |
| **训练数据** | 82 训练 + 16 验证（单类别框标注） | 353 训练 + 90 验证（4 类分类） |

> **为什么第 1 层只有 1 个类别、看不出成熟度？**
> 因为它是**检测层**，只负责**定位**。成熟度判定全部交给第 2 层。
> 这样好处有两点：① 标注时只要画框，不用选类别，工作量小很多；② 可以直接复用已经训好的成熟度分类模型。
> 所以第 1 层的指标只有 mAP（定位精度），**本身不含任何成熟度信息** —— 成熟度指标属于第 2 层。

### 交付的对照图怎么看

每张交付图都是**上下两栏**：

- **上栏（蓝色框 + 蓝字）** = **第 1 层**输出，标签是 `persimmon 0.82`，只有位置和检测置信度
- **下栏（绿色框 + 黄字）** = **两层的最终结果**，标签是 `着色期（橙红）92%`，即成熟度判定

## 四、质量分析

### 已经做好的部分 ✅

| 项目 | 表现 |
|---|---|
| **误框（假正例）** | **0 个**。手、手臂、树枝、叶子都没被框成柿子 |
| **重复框** | **0 个**。同一颗果子没有出现多个框 |
| **框定位精度** | 好。每个框都准确套在真实果子上 |
| **第 2 层成熟度判定** | 合理。橙色果子判为「转色期 / 着色期」，符合实际，置信度普遍很高 |
| **两层串联** | 正常。检测出框 → 裁图 → 分类 → 在框上标注中文 |
| **中文显示** | 正常 |
| **推理速度** | 快。稳定后单张图约 40 ms 检测 + 40~90 ms 分类 |

### 存在的问题 ❌

**唯一但严重：漏检，且漏检率随目标变小而急剧恶化。**

| 测试图 | 目标在画面中的大小 | 第 1 层召回率 |
|---|---|---|
| 图 1（手拿大柿子） | 很大（占画面 1/4 以上） | 约 30% |
| 图 2（近景一丛） | 中等 | 约 43% |
| 图 3（整棵树） | **很小（约 10~40 像素）** | **约 2%** |

规律非常清晰：**果子越小，越漏**。

## 五、根因分析

检查第 1 层的训练数据后发现：

```
检测训练集（单类别 persimmon）按原始成熟度分类统计：

  train 82 张  →  100% 都是 1_unripe（未熟·青绿）
  val   16 张  →  100% 都是 1_unripe（未熟·青绿）
  负样本        →  0 张
```

由此产生三个能力缺口：

### 缺口 1：从没学过「小目标」（**这是最主要的原因**）

训练图全是**近景大果**（果子在画面里上百像素）。YOLO 内部有三个不同尺度的检测分支，小目标靠浅层负责 —— 但那部分**从没被训练过**，所以面对十几像素的小果子完全失效。

### 缺口 2：从没学过「什么不是柿子」（负样本 = 0）

模型只学过"这是柿子"，没学过"这不是柿子"。本次三张图**没有暴露**这个问题（手、树叶都没被误框），但换到人脸、室内、其他水果等场景随时可能出现高置信度误框。

### 缺口 3：成熟度覆盖不全

用 4 个成熟度阶段的图实测第 1 层检测器（每类抽 20 张）：

| 成熟度 | 出框的图 | 平均每图框数 |
|---|---|---|
| `1_unripe` 未熟 | **20 / 20　100%** | 5.7 |
| `2_turning` 转色期 | **20 / 20　100%** | 11.9 |
| `3_coloring` 着色期 | 14 / 20　70% | 3.7 |
| `4_full` 完熟 | 10 / 20　50% | 1.7 |

**越熟越容易漏**（100% → 100% → 70% → 50%）。原因是训练时 `hsv_s = 0.7` 的颜色抖动只能补偿部分色泽变化，深红超出了覆盖范围。

> 说明：这是**第 1 层定位**的召回问题，与第 2 层的成熟度判定无关。第 2 层只要拿到框，判定是准的。

## 六、已实测排除的方案

| 尝试过的办法 | 实测结果 | 结论 |
|---|---|---|
| **提高推理分辨率** `imgsz` 640 → 1280 → 1600 | 三张图的框数几乎没有变化（3/3/3、6/4/10、3/3/2） | ❌ **无效** |
| **切图检测**（把大图切块分别检测再合并） | 框数大幅增加（3→24、6→42、3→8），**但引入了明显的叶子假正例，重复框也回来了** | ⚠️ 有潜力，但当前会牺牲精确率 |

**说明**：模型没学过的尺度，靠推理技巧只能部分弥补，而且代价是精确率下降。**没有免费午餐。**

## 七、改进方案（按性价比排序）

| 优先级 | 做什么 | 需要标注吗 | 解决什么 |
|---|---|---|---|
| **1** | **加负样本**：收集"没有柿子的图"（脸部、手、叶子特写、树枝、室内、其他水果），放进 `images/train`，并在 `labels/train` 建**同名空 `.txt`** | **不需要** | 根治误框 |
| **2** | **加远景 / 小目标图**：整棵树、多果远拍，每张都画框 | 需要画框 | **根治漏检（最关键）** |
| **3** | 补 `3_coloring` / `4_full` 熟果图，每类 30~60 张 | 需要画框 | 熟果漏检 |
| **4** | 重训时把 `imgsz` 提到 1280，并把小目标图一起训 | — | 小目标检测能力 |
| **5** | 补完数据后，把切图检测做成 `config` 开关打开 | — | 进一步提升远景召回 |

**关键点**：优先级 1 和 2 是**根本解法**，做完之后第 5 项的切图检测才能真正干净地工作（召回高 + 假正例少）。

## 八、结论

1. **两层架构与代码是通的** —— 检测、裁剪、分类、中文标注、时序平滑、阈值调优均已验证有效。
2. **第 2 层（成熟度）工作正常** —— 检出的 12 个框全部给出了合理的成熟度判定，置信度普遍很高。
3. **第 1 层（检测）精确率达标** —— 零误框、零重复框、定位准确。
4. **第 1 层的召回率是当前瓶颈，属数据问题** —— 训练集只有 82 张青柿子近景图，模型只会认"近景大果"。
5. **当前适用范围**：摄像头**近景**拍几颗柿子可用；**远景 / 整棵树**场景不可用。
6. **下一步唯一有效的工作是补训练数据**，重点是**远景小目标图**和**负样本**。
