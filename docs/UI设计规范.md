## 一、设计原则

### 1.1 三条核心原则

| 原则 | 具体做法 |
|---|---|
| **颜色即信息** | 成熟度用颜色表达，且只用于成熟度。其他 UI 元素不许用橙红色，避免语义污染 |
| **一屏搞定** | 检测页不滚动：左边看图、右边看结果。用户上传后不用翻页 |
| **结果优先** | 页面上最抢眼的是**框和成熟度**，不是导航和按钮 |

### 1.2 关于成熟度配色（**本设计的核心**）

成熟度是本系统的业务语义，颜色取自**实测各类果实的平均色相**：

| 成熟度 | 中文 | 色值 | 依据 |
|---|---|---|---|
| `1_unripe` | 未熟（青绿） | `#7EC850` | 实测平均色相 H≈63° 黄绿 |
| `2_turning` | 转色期（黄橙） | `#E8B33A` | H≈53° 黄橙 |
| `3_coloring` | 着色期（橙红） | `#E87A2A` | H≈36° 橙红 |
| `4_full` | 完熟（深红） | `#D33B3B` | H≈30° 深红 |

> **这四个颜色是全站唯一允许出现的橙红色系。** 按钮、链接、图标一律不用，否则用户会分不清"这是操作按钮"还是"这是成熟度"。

## 四、间距与布局

### 4.1 间距基数：4px

所有间距必须是 `4 / 8 / 12 / 16 / 20 / 24 / 32 / 40` 之一。**禁止出现 5px、13px、18px。**

### 4.2 栅格

| 项 | 值 |
|---|---|
| 页面最大宽度 | 1280px |
| 页面左右内边距 | 24px |
| 卡片间距 | 16px |
| 卡片内边距 | 20px 或 24px |
| 表单控件高度 | 36px（默认）/ 32px（小）/ 40px（大） |

### 4.3 断点

| 断点 | 宽度 | 布局变化 |
|---|---|---|
| 桌面 | ≥ 1200px | 检测页左右分栏（图 2/3 + 结果 1/3） |
| 平板 | 768 ~ 1199px | 检测页上下堆叠 |
| 手机 | < 768px | 单列，导航收进汉堡菜单 |

## 七、交互与状态规范

### 7.1 三种必须处理的状态（**新手最容易漏**）

| 状态 | 视觉 | 文案 |
|---|---|---|
| **加载中** | 骨架屏或 spinner | "识别中…" |
| **空数据** | 线框插画 + 居中 | "还没有识别记录" + 引导按钮 |
| **出错** | 红色图标 + 说明 + 重试按钮 | 具体原因，不要只说"失败" |

### 7.2 反馈时机

| 操作 | 反馈方式 | 时长 |
|---|---|---|
| 上传成功 | 无需提示，直接进入识别 | — |
| 识别中 | 按钮禁用 + spinner + 进度条 | — |
| 识别成功 | 直接展示结果 | — |
| 识别失败 | `ElMessage.error` 顶部提示 | 3 秒 |
| 保存到历史 | `ElMessage.success('已保存')` | 2 秒 |
| 删除记录 | `ElMessageBox.confirm` 二次确认 | — |

### 7.3 防重复提交

**识别按钮点击后必须立刻禁用**，识别完成或失败才恢复。
理由：后端单卡 GPU 是**串行排队**的，用户连点 5 次会排 5 个任务，后面 4 次全是白等。

### 7.4 首次识别的特殊提示

```
首次识别较慢（约 15 秒），因为要加载模型
之后每次只需 0.2 秒左右
```

**必须显示这段文字**，否则用户会以为程序卡死。
