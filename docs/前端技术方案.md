## 一、项目背景与目标

### 1.1 是什么

一个基于 YOLO 两层模型的柿子成熟度识别系统：上传一张柿子照片，系统框出每一个柿子并判断它属于哪个成熟度阶段。

### 1.2 为什么做前端

| 目的 | 说明 |
|---|---|
| **作品集** | 作为全栈实习的完整项目，需要能演示、能讲架构 |
| **可用性** | 命令行工具只有自己会用，网页别人也能用 |
| **技术展示** | 体现前端工程化能力（这是全栈岗的加分项） |

### 1.3 本期目标（Definition of Done）

做到以下三点就算本期完成：

1. 能上传图片 → 看到框和成熟度
2. 能查看历史记录 → 数据存在数据库里，刷新不丢
3. 能登录 → 多用户数据隔离

**上线（能被外网访问）作为加分项，不阻塞本期验收。**

## 三、技术选型

### 3.1 选型表

| 类别 | 选择 | 版本 | 理由 |
|---|---|---|---|
| 框架 | **Vue 3** | 3.4+ | 国内 Web 公司主流；组合式 API 易上手；生态成熟 |
| 构建 | **Vite** | 5.x | 冷启动秒级；配置极少；官方脚手架 `npm create vue@latest` |
| 路由 | **Vue Router** | 4.x | Vue 官方标准方案 |
| 状态 | **Pinia** | 2.x | Vue 官方推荐；只有 `user` 和 `task` 两个 store |
| UI 库 | **Element Plus** | 2.x | 表格/上传/弹窗开箱即用，省一半工作量 |
| HTTP | **Axios** | 1.x | 拦截器统一处理 token 和错误 |
| 语言 | **JavaScript** | ES2022 | ⚠️ 见 3.2 |
| 包管理 | **npm** | 自带 | 不引入 pnpm/yarn，减少变量 |

### 3.2 ★ 关于是否用 TypeScript（重要决策）

**决策：本期用 JavaScript，不用 TypeScript。**

理由：

```
目标优先级：  完成项目  >>  技术栈齐全
```

- 你目前只系统学过 JS，上 TS 会额外花 3~5 天在类型报错上
- 一个**做完的 JS 项目**，远胜一个**没做完的 TS 项目**
- 后端接口已经用 Pydantic 做了校验（Python 侧），前端类型错误的实际风险下降了

**升级路径**：P5（上线）完成后，如果还有时间，可以按"文件逐个改"的方式迁移到 TS，不影响功能。

> **面试怎么说**：
> "我先用 JavaScript 把功能闭环做完，因为我的目标是交付一个完整可用的系统；类型安全我在后端用 Pydantic 做了。如果团队需要 TS，我可以迁移 —— 我了解 TS 的价值主要在多人协作时的接口契约。"

**分层纪律**：

| 层 | 该做什么 | 不该做什么 |
|---|---|---|
| `views/` | 组织页面、调 store、组装组件 | **不直接写 axios** |
| `components/` | 展示与交互，通过 props/emit 通信 | 不发请求、不读 store（除非是业务组件） |
| `api/` | 发 HTTP、拼参数、统一错误 | 不做业务判断、不碰 UI |
| `stores/` | 跨页面共享的状态 | 不做请求细节 |

| 路由 | 页面 | 是否需登录 | 说明 |
|---|---|---|---|
| `/login` | 登录页 | ❌ | |

**路由守卫逻辑**：

```

登录成功后 → 跳回 redirect，没有就跳 /detect
```

## 六、接口契约

### 6.1 架构说明（**开发阶段和正式阶段不一样**）

```
开发阶段（P1 还没做完时）：
    前端  ──直接调──>  Python 服务 :8001     ← 快，能立刻联调

正式阶段（P1 完成后）：
    前端  ──>  Java 业务后端 :8080  ──HTTP──>  Python 推理服务 :8001
              （管用户/历史/权限）              （只管推理）
```

**做法**：前端所有请求都走 `/api/*` 相对路径，**具体连谁由 Vite 代理决定**。这样切换后端时前端代码一行都不用改。

```js
// vite.config.js
export default defineConfig({
  server: {
    proxy: {
      // 开发阶段：直接转给 Python
      '/api/predict':  { target: 'http://127.0.0.1:8001', changeOrigin: true },
      // 其他接口转给 Java（P1 完成后启用）
      '/api':          { target: 'http://127.0.0.1:8080', changeOrigin: true },
    }
  }
})
```

### 6.2 识别接口（P0 已完成，可直接用）

```
POST /api/predict
Content-Type: multipart/form-data
Body: file=<图片文件>
```

响应：

```json
{
  "ok": true,
  "image": { "width": 1280, "height": 1865 },
  "detections": [
    {
      "box": [551, 158, 839, 438],
      "det_conf": 0.916,
      "ripeness": "3_coloring",
      "ripeness_label": "着色期（橙红）",
      "ripeness_conf": 0.9169
    }
  ],
  "counts": { "1_unripe": 0, "2_turning": 0, "3_coloring": 6, "4_full": 0 },
  "timing": { "detect_ms": 42.1, "classify_ms": 86.3 },
  "error": null
}
```

**前端需要注意的三点**：

1. `box` 是**原图像素坐标**，不是显示坐标 → 画框时必须按 `显示尺寸/原图尺寸` 换算（见 7.1）
2. **`ok: false` 和 HTTP 4xx/5xx 是两回事** → 拦截器要同时处理
3. 一张柿子都没有时 `detections` 是**空数组**，`ok` 仍为 `true` → 这是正常结果，不是错误

### 6.3 其他接口（P1 Java 提供，前端先按此约定开发）

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/auth/login` | 登录，返回 `{token, username}` |
| `POST` | `/api/auth/logout` | 退出 |
| `GET` | `/api/history?page=1&size=10` | 分页列表 |
| `GET` | `/api/history/{id}` | 详情（含 detections） |
| `DELETE` | `/api/history/{id}` | 删除 |
| `GET` | `/api/stats/summary` | 各类成熟度总数 |
| `GET` | `/api/stats/trend?days=30` | 按天趋势 |

> **前后端并行开发的关键**：P1 还没做完时，前端可以先用 **Mock**（`vite-plugin-mock` 或直接写死在 `api/` 里），不要卡住。

## 七、关键技术方案

### 7.1 ★ 画框组件（最容易踩坑的地方）

**问题**：图片用 CSS 缩放显示，但 `box` 是原图像素坐标。窗口一变尺寸，框就错位。

**方案**：

```
组件结构
┌─────────────────────────┐
│ <div class="stage">     │   position: relative
│   <img>                 │   max-width: 100%
│   <canvas>              │   position: absolute; left:0; top:0
│ </div>                  │
└─────────────────────────┘
```

```js
// 换算比例
const sx = img.clientWidth  / img.naturalWidth
const sy = img.clientHeight / img.naturalHeight
const X = box[0] * sx,  Y = box[1] * sy
const W = (box[2] - box[0]) * sx,  H = (box[3] - box[1]) * sy
```

**必须处理的三件事**：

1. `img.onload` 之后才能算尺寸（`naturalWidth` 在加载完成前是 0）
2. `window.resize` 时**重绘**（比例变了）
3. 图片切换时**先清空 canvas**（`clearRect`）

### 7.2 文件上传

```js
const fd = new FormData()
fd.append('file', file)
```

**要做校验**：

| 校验 | 值 | 时机 |
|---|---|---|
| 类型 | jpg/jpeg/png/bmp/webp | 选择文件时 |
| 大小 | ≤ 20 MB（后端也是这个限制） | 选择文件时 |

**为什么前端也要限制**：后端限制超了会返回 413，用户要等上传完才知道，体验差。**前端先拦，秒回提示。**

> 后续优化（可选）：用 `canvas` 把大图先压到长边 1920 再上传 —— 你的相机原图有 27 MP / 14 MB，压缩后上传快很多。

### 7.3 HTTP 拦截器（统一处理）

```js
// api/request.js 要做四件事
1. 请求拦截：自动带上 Authorization: Bearer <token>
2. 响应拦截：code 401 → 清 token → 跳登录页
3. 响应拦截：其他错误 → ElMessage.error 统一提示
4. 超时设置：识别接口要 60 秒（首次可能慢），其他 15 秒
```

### 7.4 状态管理（只建两个 store）

```js
// stores/user.js
state:   { token, username }
actions: { login(), logout() }

// stores/detect.js
state:   { 当前图片File, 当前结果, loading }
actions: { runDetect() }
```

**为什么 detect 也要用 store**：检测页拿到结果后，跳到详情页/统计页要用同一份数据，放 store 比传参干净。

**⚠️ 不要什么都往 store 里放。** 只有"跨页面共享"的才放；组件内部状态（比如弹窗开关）留在组件里。

| 类型 | 规范 | 例子 |

feat:  新功能        feat: 检测页支持拖拽上传

## 十、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 后端 P1 迟迟不做完 | 前端卡住 | **先接 Python 的 `/api/predict`**，历史/登录先用 Mock |
| 大图上传慢 | 体验差 | 前端压缩；后端已限 20 MB |
| 首次识别慢（模型冷启动） | 用户以为卡死 | 后端启动就预加载；前端显示"首次较慢"提示 |
| 并发识别排队 | 多用户时变慢 | 后端加锁串行；前端禁用按钮防重复提交 |
| 跨域问题 | 请求失败 | Vite proxy（开发）/ Nginx 反代（生产） |
