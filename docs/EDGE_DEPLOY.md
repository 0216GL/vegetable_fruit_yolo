# 边缘部署方案（二期）

> 2026-10-11 建立。**这份文档目前只是方案和验证清单，不是已完成的能力。**
>
> ⚠️ **截至今天，边缘设备上一次都没跑过**：没选过平台、没导过 ONNX、
> 没在任何开发板上测过帧率 / 内存 / 功耗。**材料里不能写成"已支持边缘部署"。**

---

## 一、为什么要做边缘（而不是继续用现在的 Web 架构）

一期是「手机端 H5 + 本地推理服务」，手机上拍照后要把图传到服务端才能出结果。这套在
**产地现场**有三个硬伤：

| 问题 | 现场实际情况 |
|---|---|
| 没网 | 果园、分选棚经常没有可靠 WiFi，蜂窝信号也不稳 |
| 数据顾虑 | 农户/合作社不愿意把果园照片传到外部服务器 |
| 延迟 | 一期是"传图 → 等 → 回结果"，交互上不适合连续识别 |

边缘部署要解决的就是这三条：**推理跑在本地设备上，断网也能用。**

## 二、和一期路线的关系

按 `PRODUCT.md` 定的**分阶段双场景**：

- **一期（现在能演示）**：近景 / 分选台 + 手机拍照 → 网页 + 服务端推理
- **二期（本文件）**：果园 / 分选台的**边缘设备摄像头** → 本地离线推理

**二期有个前提没解决**：果园边缘设备如果是"看树"，就正对着检测模型的短板
（整树召回约 30%、负样本仍为 0、漏检约 70%）。所以二期的顺序是
**先补远景数据把召回做上来，再上边缘设备**，不能反过来。

## 三、实测基线（2026-10-11，本机）

跑边缘之前先知道自己离目标多远。用《新测试图_第二轮/2_(103).jpg》测的：

| 设备 | 检测耗时（imgsz=640） | 等效帧率 |
|---|---|---|
| **笔记本 CPU**（无 GPU 加速） | **50.2 ms / 张** | **19.9 FPS** |
| 笔记本 GPU（RTX 4050 Laptop） | 26.5 ms / 张 | 37.7 FPS |

**几个读数：**

- 这个模型**不依赖 GPU** —— 纯 CPU 就能到 20 FPS，说明算力门槛没有想象中高
- 但这是 **x86 笔记本 CPU**。ARM 开发板的 CPU 单核性能通常只有它的 1/3~1/2，
  纯 CPU 很可能掉到 5 FPS 上下 —— **要不要 NPU，取决于这个数能不能接受**
- 两层模型合计 **8.27 MB**（检测 5.22 + 分类 3.04），内存占用不是瓶颈

> ⚠️ 上面是**笔记本上**的实测。**开发板上的数字一个都没测过**，选型前必须自己测。

## 四、候选平台（规格来自官方页面，未在本项目验证）

| 方案 | 标称算力 | 大致成本 | 特点 |
|---|---|---|---|
| [NVIDIA Jetson Orin Nano Super 开发套件](https://www.nvidia.com/en-us/autonomous-machines/embedded-systems/jetson-orin/nano-super-developer-kit/) | 官方标称 67 TOPS（INT8） | 开发套件约 $249 | 生态最成熟，PyTorch/ONNX/TensorRT 支持最好，**最省事** |
| [Raspberry Pi 5 + AI Kit（Hailo-8L）](https://www.raspberrypi.com/products/ai-kit/) | 13 TOPS | AI Kit 官方 $70 + Pi 5 单买 | 最便宜，社区资料多；Hailo 需要模型转成专用格式，**移植工作量最大** |
| [瑞芯微 RK3588 方案（香橙派 5 / Rock 5B 等）](http://www.orangepi.cn/orangepiwiki/) | NPU 6 TOPS | 千元内（含板 + 存储） | 国产、供货稳、性价比高；RKNN 工具链有其坑，资料比前两者少 |

**倾向：先用 Jetson Orin Nano Super。** 理由是"把模型跑起来"这件事上它的路径最短
（`.pt → ONNX → TensorRT` 有官方支持），二期目标是把链路打通，不是省那点硬件钱。
等链路验证完，再评估换更便宜的板子。

**但这是建议，不是结论** —— 真实成本、供货、功耗都要等实测。

## 五、验证清单（二期第一件事，按顺序做）

```
[ ] 1. 导出 ONNX（检测 + 分类两个模型各一份），确认输出和 PyTorch 一致
[ ] 2. 选一块板子（建议 Jetson Orin Nano Super），拿到手
[ ] 3. 在板上跑通单图推理，记录：帧率 / 峰值内存 / 功耗 / 板子温度
[ ] 4. 换 ARM CPU 纯推理再测一遍，和"加 NPU"对比 —— 决定 NPU 到底值不值
[ ] 5. 摄像头实时链路（V4L2 / GStreamer）跑通，测连续 10 分钟的稳定性
[ ] 6. 断网验证：拔网线/关 WiFi，确认功能不受影响
[ ] 7. 把实测数字补进本文件，并同步 `docs/TECH_DATA.md`
```

**在清单第 3 项做完之前，任何材料都不能出现"已支持边缘部署""可在边缘设备运行"这类说法。**

## 六、和现有代码的关系

边缘端**不需要重写推理逻辑**：`ai/inference.py` 已经是两层推理的单一入口
（检测 → 逐果裁剪 → 分类 → 返回统一结构），边缘端只要替换"图片从哪来"
（本地文件 → 摄像头帧）和"模型怎么跑"（PyTorch → ONNX Runtime / TensorRT）。

`ai/server/`（FastAPI）在边缘场景**可以不用** —— 那是给一期的 Web 架构准备的。
