## 6. 模型

| 项目 | 值 |
|---|---|
| 框架 | Ultralytics |
| 版本 | **YOLO11** |
| 规模 | **n（nano，最小号）** |
| 分类模型 | `yolo11n-cls`，86 层，**154 万参数**，3.3 GFLOPs，3.05 MB |
| 检测模型 | `yolo11n` |
| 训练轮数 | 配置 100，**早停 patience=10，实际第 38 轮停止** |
| 输入尺寸 | 224×224（分类） / 640×640（检测） |
| 批大小 | 16 |
| 优化器 | auto |
| 预训练 | **ImageNet 迁移学习**（继承 234/236 层权重） |
| 硬件 | NVIDIA RTX 4050 Laptop，6 GB |

### 数据增强（★ 这是本项目的技术亮点）

| 参数 | Ultralytics 默认 | 本项目用了 | 为什么改 |
|---|---|---|---|
| `hsv_h`（色相） | 0.015（±5.4°） | **0.0** | 着色期与完熟期**平均色相只差 6°**，乱抖就把关键信号毁了 |
| `hsv_s`（饱和度） | **0.7（±70%）** | **0.2** | 默认值等于告诉模型"饱和度不用管"，而这任务就是看颜色 |
| `hsv_v`（亮度） | 0.4 | 0.3 | 保留真实光照差异 |
| `auto_augment` | randaugment | **关闭** | 里面含 Color/Posterize/Solarize，进一步破坏颜色 |
| `erasing` | 0.4 | **0.15** | 默认太容易把果实整个遮掉 |

**支撑这个决定的实测数据**（各类平均色相）：

```
未熟 62.7°  →  转色期 53.2°  →  着色期 35.6°  →  完熟 29.5°
```

相邻两级只差 6~18°，而默认增强的抖动幅度几乎覆盖了这个差距。

### ★★★ 最重要的一处更正：那个"最大问题"已经被修好了

README 和旧文档反复强调「**着色期 ↔ 完熟 混淆是最大问题**，着色期召回只有 64%」。
**这个结论是基于旧模型（84.44%）的，现在已作废。**

| | 旧模型（84.44%） | **新模型（88.89%）** | 变化 |
|---|---|---|---|
| **着色期** 召回率 | **64.00%** ← 最差 | **88.00%** | **+24 个百分点** |
| 完熟 召回率 | 94.74% | 89.47% | −5.27 |
| 着色期→完熟 误判 | 28%（25 张错 7 张） | **11%** | 大幅收窄 |
| 完熟→着色期 误判 | — | **8%** | — |

**结论：修正数据增强参数（`hsv_s` 0.7→0.2、关掉 `auto_augment`）确实起作用了，
而且改善最大的正是原先最差的那条边界。**

**新的最弱类别变成了「转色期」（召回 74%）**，它被两边挤：
11% 被判成未熟，16% 被判成着色期。原因是它处在整条成熟连续体的**正中间**，
两侧都没有明确的色相边界。

> **这是一个非常完整的"发现问题 → 定位原因 → 修正 → 验证改善"的实验故事，
> 是整份材料里最有说服力的部分。答辩时重点讲这个。**

### ★★★ 检测层（第 1 层）—— 这才是真正的瓶颈

> 来源：`artifacts/分析报告_2026-09-26_第一轮.md`（2026-09-26 第一轮，补数据**前**的实测）、`artifacts/报告_2026-09-27_第二轮.md`（2026-09-27 第二轮，补数据后重测）。
> **这是整份材料里最重要、也最容易被忽略的一段。**

**指标：**

| 项目 | 值 |
|---|---|
| mAP@0.5 | **90.87%**（补数据前为 88.23%，属 09-26 历史值） |
| 训练 / 验证 | **92 / 16 张**（共 108） |
| 类别数 | 1（只叫 `persimmon`，不含成熟度） |

**⚠️ 但训练集有一个致命问题：**

```
train 92 张  →  100% 都是 1_unripe（未熟·青绿）
val   16 张  →  100% 都是 1_unripe（未熟·青绿）
负样本        →  0 张
```

**也就是说：检测模型只见过"近景、大果、青绿色"的柿子，没见过别的。**

**实测表现（真实照片，3 张；2026-09-26 第一轮、补数据前的历史实测）：**

| 测试图 | 目标大小 | 检出 / 目测可见 | **召回率** |
|---|---|---|---|
| 手拿大柿子 | 很大（占画面 1/4+） | 3 / 约 10 | 约 30% |
| 近景一丛 | 中等 | 6 / 约 14 | 约 43% |
| **整棵树** | **很小（10~40 像素）** | **3 / 约 200** | **约 2%** |

> **2026-09-27 第二轮（补小目标数据重训后）重测**（`artifacts/报告_2026-09-27_第二轮.md`，9 张测试图共 137 个框）：
> 整棵树 **3 → 61 个框（约 30%）**；手拿大柿子 3 个框、近景一丛 6 个框，**前后都是 ±0（没改善）**；
> 负样本仍为 0，整棵树**仍有约 70% 漏检**。检测 mAP@0.5 也从 88.23% 提到 **90.87%**。

**规律非常清晰：果子越小，漏得越狠。**

**另外，越熟越容易漏**（每类抽 20 张实测第 1 层出框率）：

| 成熟度 | 出框的图 | 平均每图框数 |
|---|---|---|
| 未熟 | **20/20（100%）** | 5.7 |
| 转色期 | **20/20（100%）** | 11.9 |
| 着色期 | 14/20（70%） | 3.7 |
| 完熟 | **10/20（50%）** | 1.7 |

**原因是训练集全是青果——模型没见过红的。**

**但精确率是好的：**

| 项目 | 表现 |
|---|---|
| 误框（假正例） | **0 个**。手、手臂、树枝、叶子都没被框成柿子 |
| 重复框 | **0 个** |
| 框定位精度 | 好，每个框都准确套在果实上 |

**已经实测排除的方案（这段很值钱，说明真试过）：**

| 试过的办法 | 实测结果 | 结论 |
|---|---|---|
| 提高推理分辨率 `imgsz` 640→1280→1600 | 框数几乎没变 | ❌ **无效** |
| 切图检测 | 框数大增（3→24、6→42），**但引入明显叶子误框、重复框回归** | ⚠️ 有潜力，目前牺牲精确率 |

> **这两条是答辩的加分项**：说明不是没想办法，而是**试过、量化过、知道为什么不行**。

**改进方向（按性价比）：**

| 优先级 | 做什么 | 要标注吗 |
|---|---|---|
| 1 | **加负样本**（手、脸、叶子特写、室内、其他水果），配同名空 `.txt` | **不用** |
| 2 | **加远景 / 小目标图**，整棵树、多果远拍，每张画框 | 要画框 |
| 3 | 补着色期 / 完熟的熟果图，每类 30~60 张 | 要画框 |
| 4 | 重训时把 `imgsz` 提到 1280，和小目标图一起训 | — |

**★ 和太行山采集的关系：** 2026-10-04 采的那 100 多张**正好补的就是优先级 2 和 3**
（整树多果、真实果园环境）。**但需要画框标注才能用来训检测模型。**

## 8. 有没有改进、有没有对比

### ✅ 有改进，而且理由说得清（这是亮点）

**改进内容**：修正数据增强参数（见第 6 节表格）。

**改进依据**：先实测了四个成熟度类别的平均色相（62.7°/53.2°/35.6°/29.5°），
发现相邻两级只差 6~18°，而 Ultralytics 的默认增强是为**目标检测**设计的，
`hsv_s=0.7` 会把饱和度抖 ±70%——**等于主动破坏这个任务最核心的信号**。

> **这段是整份材料里最能体现"真做过实验"的部分**，答辩时要重点讲。
> 因为它说明：不是照抄教程跑了个模型，而是**发现默认参数和任务不匹配，找出了原因并修正**。

### ✅ 有对比（一个）

同一份物种数据，用 **sklearn + 手工特征（HSV 直方图 + HOG）+ SVM** 只能到 **63.68%**，
而迁移学习到 **97.95%**。

**结论**：差距来自迁移学习，不是数据本身简单。

### ❌ 没有的（评审可能问）

| 缺什么 | 补的难度 |
|---|---|
| 与其他 YOLO 规模对比（n/s/m/l） | 低，改一行参数重训，几分钟 |
| 与其他模型对比（ResNet50 / EfficientNet） | 中，要另写训练脚本 |
| 模型结构改进（本项目的创新点） | 高 |
| 消融实验（每个增强参数单独的影响） | 中 |

> ⚠️ **诚实提醒**：目前**没有算法层面的创新**，用的是现成的 YOLO11n + 迁移学习。
> 材料里如果要写"技术创新点"，建议如实写成**"针对任务的参数适配"**，
> 而不是暗示做了模型结构改进——**评委会追问的**。

### ★ 最重要的一句话

**#1 不是"补个数字"，是"补一个能力"。**

现在 `PRODUCT.md` 里写着"单果级，不是地块级"——那是**产品的定位**。
但检测层在整树照片上仍有约 70% 的果找不到（补数据后召回约 30%），**这个定位目前还撑不起来**。
