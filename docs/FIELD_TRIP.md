## 〇、为什么这趟特别重要

项目里 `.gitignore` 有这么一行：

意思是：**现在模型用的那 446 张柿子图，是最后一份。删了就没了，也补不了。**

而模型有个已知的硬伤：**「着色期」和「完熟期」分不清** —— 25 张里错 7 张，召回率只有 64%。

**明天是修这个问题的唯一机会。** 而且不用花很多时间——你的模型重训一次只要 147 秒。

## 一、拍什么（按优先级，时间不够就砍下面的）

### ★ 最高优先级：边界样本（至少占一半）

**你觉得"这颗到底算橙还是红、拿不准"的 —— 那才是最有价值的样本。**

模型就是在这些图上翻车的。所以专门去找：

- 橙色偏红的果子（着色期和完熟之间）
- 红色偏橙的果子
- **同一棵树上，颜色明显不一样的两颗，一起拍进一张**
- 同一颗果子，转到不同角度拍（有些面更红）

单独建一个文件夹叫 **`拿不准`**，把这些全丢进去。**不用勉强分类。**

### 高优先级：四种成熟度各拍一批

| 文件夹 | 什么样子 |
|---|---|
| `未熟` | 青绿，硬的 |
| `转色期` | 黄橙，开始变色 |
| `着色期` | 橙红（**这是模型最弱的一类，多拍**） |
| `完熟` | 深红，软的 |

### 中优先级：整树和果园（检测模型要用）

- 一棵树上**挂满果子**的中景/远景
- 有枝叶遮挡的（真实场景里就是会被挡）
- 逆光的、树荫下的
- 果园全景、地形、柿子树的样子

### 顺便拍：比赛的素材

- **果农在果园里干活的照片**（背身、侧脸比正脸自然）
- 手拿柿子的特写
- 摘柿子、装筐、晾晒柿饼的场景
- 一小段视频（10-30 秒，果农说几句话，**要先问能不能拍**）

## 二、怎么拍（这几条直接影响数据能不能用）

**1. 别只拍白底特写。** 现在的模型有个毛病：它学到的其实是"浅色背景 + 中间有个东西"，
不是"柿子"本身。所以**一定要带真实环境**——枝叶、天空、阴影都留着。

**2. 光照一定要多样。** 顺光、背光、树荫下、阴天、早上、中午，都要有。
只拍一种光，模型会学成"亮的 = 熟的"，那就完了。

**3. 不要开美颜、不要加滤镜、不要开 HDR。** 这些会改颜色，而颜色就是这个模型的命根子。
拍之前**擦一下镜头**（果园里镜头容易有灰和水汽）。

**4. 走近拍，不要用数码变焦。** 变焦会让画面糊，糊掉的图对训练没用。

**5. 每张尽量只让一颗果子当主角**（分类模型是裁出单颗来判的），
但也别太死板，顺带拍到旁边几颗没关系。

**6. 一个可选的加分项：** 每换一种光照条件，先拍一张**白纸或灰纸**。
以后可以用它校正色差。不麻烦，有更好。

**目标数量：200–400 张。** 其中一半以上是"拿不准"的边界样本。多拍不要紧，删起来快。

## 四、问农户什么

> 2026-10-03 重写。加进了能**直接决定「三类还是四类」**的问题。
> 原则：先开放地问，不给他选项 —— 才知道他心里真实的分类是什么样。

### A. 先搞清他的心智模型（别引导，让他自己说）

1. **您怎么知道柿子能摘了？** 看颜色？用手捏？还是看日子？
2. **柿子从青到熟，您能看出几个阶段？**（★ 关键：**不要提示"四个"**，让他自己数。
   他说三个，就是三个；他说五个，也有价值）
3. **哪两个阶段之间最难分？**（★ 问他觉得哪儿模糊。
   可能和我们模型发现的不是一个地方 —— 那就是新信息）
4. 同一棵树上，果子熟得一样吗？差多少？

### B. 决定「三类还是四类」的问题（★ 最重要）

模型的四级是：青绿 / 黄橙 / 橙红 / 深红。
问题出在**橙红和深红分不开**。所以直接问他这两级有没有区别：

5. **一个橙红的、一个深红的，您会区别对待吗？还是都算"能摘了"？**
   - 答"都一样，一起摘" → **合并成三类更合理**，模型立刻准一大截
   - 答"不一样" → 追问下去，**四类必须保**
6. **同一片园子，您会分几次摘？**（如果一次全摘完，细分就没意义）
7. **深红的和橙红的，用途一样吗？**（比如深红做柿饼、橙红鲜卖 → 那必须分开）
8. **摘早了会怎么样？摘晚了会怎么样？**（问出具体后果和损失，这是项目的痛点依据）

### C. 价格和销路（产品的商业逻辑）

9. 不同等级的柿子，价格差多少？（**能问出具体数字最好**）
10. 卖给谁？收购商上门收，还是自己拉出去？
11. 主要做什么用？鲜食、柿饼、还是送加工厂？

### D. 工具和意愿（可能推翻我们的设计）

12. 现在靠经验，还是有什么土办法/工具？
13. **如果手机拍一张照，就能告诉您哪颗能摘、大概什么时候摘，您会用吗？**
14. **您最希望它告诉您什么？**（★ 这一问最值钱。
    如果他说"我就想知道几号能摘"，那"成熟度百分比"这个输出形式就得改）

### E. 最后

15. **能不能留个联系方式？以后有问题想请教您。**
16. **能不能拍几张您在果园里的照片，或一小段视频？** 说明是学生做比赛用。

## 四之二、明天顺手做两个小实验

你说"有时候侧着刚好，有时候侧着总出错"。这句话指向两个不同的原因
（角度问题 / 光照问题），当场做个实验就能分开：

### 实验一：测角度

挑 **5 颗**颜色中等的果子（别挑明显的）。每颗拍 **4 张**：

```
果子A_正面.jpg
果子A_左30度.jpg
果子A_右30度.jpg
果子A_仰角.jpg
```

放在一个单独的文件夹 `实验_角度/`。

**回来跑一遍模型**：如果同一颗果子不同角度给出不同答案 → 角度是干扰源；
如果四个角度答案一致、但和肉眼不一致 → 是成熟度本身难分，不是角度。

### 实验二：测光照

挑 **5 颗**果子，每颗拍 **3 张**：

```
果子B_顺光.jpg     （太阳在身后）
果子B_逆光.jpg     （太阳在果子后面）
果子B_树荫.jpg     （阴影里）
```

放在 `实验_光照/`。

**回来跑**：如果顺光对、逆光错 → 说明模型学的是"亮度"而不是"颜色"，
那明天的数据就要刻意多拍逆光和阴影，把这个偏差掰回来。

> ⚠️ 这两个实验一共只要 35 张照片，五分钟的事，
> 但能把"模型到底弱在哪"从猜测变成证据。**答辩时这是很硬的一页。**

## 五、合作社该怎么办

**别一上去就谈"合作"。** 顺序应该是：

1. **先做朋友** —— 上午就跟着走、问问题、帮忙递个筐都行。柿农对"学生来问"通常是欢迎的
2. **加微信，留电话** —— 这比任何纸面东西都实在
3. **如果聊得好**，再问：能不能帮忙开一张「试用意向」或者盖个合作社的章

**关于盖章那个：** 互联网+ 比赛里，"有真实用户愿意用"是很硬的加分项。
但**要靠聊得来自然产生，不要硬要**。一张真诚的微信对话截图，有时比一张盖章的纸更有说服力。

**回来后最有效的一步：** 把 demo 做好，发给他们看，请他们提意见。
这就是真实的用户反馈，答辩时讲这个比讲"我们调研了 N 家合作社"可信得多。
