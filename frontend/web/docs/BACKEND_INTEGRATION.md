# 当前工作台接入位置（2026-10-22 更新）

最新识别页由 `dist/assets/orchard-workbench.js` 覆盖 recognize 与 bindUpload；样式在同目录 orchard-workbench.css。下方旧版行内函数位置仅供历史参考。

- 原始上传 File 保存在 orchardState.file；本地 URL 在 orchardState.url；图片宽高在 orchardState.meta。
- ow-detect 按钮仍禁用，尚未调用任何推理接口。接入真实服务时在 bindUpload 内绑定请求，使用 FormData 发送原始 File。
- orchardState.mode 的 sample 与 upload 严格分离；orchardExamples 是人工预设界面示意，不能作为用户照片的推理结果。
- 框坐标以图片相对比例存储，框与照片共享 ow-image-transform 的缩放、平移。真实 bbox 须由原图像素换算。
- 使用请求版本号取消或忽略旧图片的迟到响应。切换品类、更换图片、移除照片时清除真实检测结果。
- 机器人是透明图像加悬停、回应动画及预设文案，不是三维模型或大模型助手。
- 接入服务后同步更新本地预览隐私文案、错误/加载状态、真实检测结果字段。

# 后端对接说明

## 1. 先确认现状

本包是静态前端，**没有后端服务、模型权重、推理代码或已约定的检测接口**。用户图片只通过浏览器 Object URL 预览。下面的 API 是建议协议，需要前后端确认后实现，不是已有接口。

请保留现有首页、动画和小禾形象。后端可以直接接入当前工作台，不需要重做页面。

## 2. 代码定位

所有相关代码在 `dist/index.html`，建议直接搜索函数名，不依赖行号。

| 位置 | 作用与接入注意事项 |
| --- | --- |
| `basicRecognize()` | 生成工作台、禁用的 `.desk-primary` 按钮、`.desk-result` 结果区 |
| `bindUpload()` | 品类切换、文件选择、拖放、更换与移除处理；在这里绑定检测按钮 |
| `loadImage(file)` | 文件校验与图片解码。当前只保留 `fileUrl`、`fileMeta`，需要新增变量保存原始 `File`，供 FormData 上传 |
| `updateMeta()` | 更新图片与尺寸，切换空状态 |
| `selectedFruit` / `FRUITS` | 当前品类与品类列表，柿子 id 为 `persimmon` |
| `paintDeskView()` / `bindDeskView()` | 图片缩放和平移；检测标注必须使用同一图像坐标变换 |
| `render()` | 路由切换时重建 DOM。结果需存入独立状态，重新绑定按钮；路由离开时取消请求或忽略旧响应 |
| `answer(q)` | 小禾预设回答。若接大模型，需要单独的服务端接口，不能把 API 密钥放在这里 |

原有“移除照片”、重新选择照片、改变品类都应清空旧结果。图片解码使用 `loadVersion` 避免旧回调覆盖新状态，检测请求也需要类似的 requestId/取消机制。

## 3. 建议接口（待双方确认）

`POST /api/detect`，`multipart/form-data`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `image` | File | 原始图片文件，不是 blob: 地址，也不是本地文件路径 |
| `fruit` | string | 初期只允许 `persimmon`，其它品类未支持时返回明确错误 |

同域部署可用相对地址 `/api/detect`；分域开发时提供配置的 API_BASE_URL，并让后端配置允许的前端来源。设置 FormData 时不要手动写 multipart Content-Type，浏览器需要生成 boundary。

成功响应结构示例如下。数值只用于说明字段形状，**不是项目模型实测或前端演示结果**，不可硬编码成网页输出。

```json
{
  "request_id": "server-generated-id",
  "fruit": "persimmon",
  "model_version": "actual-model-version",
  "image": {"width": 1600, "height": 1200},
  "detections": [
    {"id": "fruit-1", "bbox": [100, 120, 360, 420], "grade": "coloring", "confidence": 0.82}
  ]
}
```

### 分级与坐标

- 建议等级枚举：`unripe` 未熟、`turning` 转色期、`coloring` 着色期、`ripe` 完熟。需要先核对模型训练标签与顺序，前端不能自行猜测类别编号。
- `bbox` 建议统一成原图像素坐标 `[x_min, y_min, x_max, y_max]`，左上角为原点；返回图像尺寸应与该坐标系一致。模型若使用 letterbox/缩放，后端应还原到原图坐标再返回。
- 前后端应约定 EXIF 方向处理，使模型坐标与浏览器看到的图片方向一致。
- `confidence` 范围为 0～1，说明是单果分类置信度，不能当成整体准确率；未提供时显示“未提供”，不要补默认数值。
- 多果图片展示各等级数量和单果详情，不能凭空给整个图像定一个总成熟度。没有检测到果实时返回空数组，不能显示为“未熟”。
- 置信度、检测阈值和模型范围由后端明确；裂纹、果梗、糖度、采摘建议等未实现能力不要返回虚构字段。

### 错误响应建议

统一 JSON，例如 `{"error":{"code":"UNSUPPORTED_FRUIT","message":"当前仅支持柿子"}}`。至少区分参数/格式错误、文件过大、未支持品类、服务未就绪、模型推理失败、网络超时。上传限制前后端一致（当前前端 15 MB），后端也需验证文件与解码结果。

## 4. 前端接入步骤

1. 在 `loadImage(file)` 成功后保留原始 File；更换/移除时释放旧引用并清空结果。
2. 给 `.desk-primary` 增加稳定 id 与点击处理；只在合法图片已载入、品类受支持、后端就绪时启用。
3. 点击后发送 FormData；显示真实“检测中”状态、避免重复提交，支持取消/超时。不要用固定等待时间伪造推理。
4. 解析返回值，更新结果区；后端未就绪仍保留本地预览功能。
5. 标注图层放在原图同一容器中。将原图坐标先按 object-fit:contain 的缩放和居中留白定位，再与图片一起缩放/平移，避免框与果实错开。
6. 成功/空结果/失败分别处理；新增结果状态必须能在 `render()` 重建 DOM 后恢复。
7. 接通真实上传后，修改当前“照片不会上传服务器”“模型待接入”等文字，准确说明新行为，不保留与实际矛盾的提示。

## 5. 联调验收

- 单果、多果、无果实、重复或遮挡果实；四个等级的实际标签映射。
- JPEG/PNG/WebP、超限与损坏图片、竖图方向、大图缩放与检测框位置。
- 检测中更换/移除图片、切换品类、跳转页面，旧结果不得覆盖新图片。
- 服务不可用、超时、失败响应、连续点击，能恢复操作。
- 手机与桌面显示正常，不影响首页动画、小禾与其它现有入口。
